# Jank Hunter для Android Studio

Плагин создаёт локальные отчёты Jank Hunter из `.jhlog`, HPROF и дополнительных артефактов Android-сборки. Ручное составление команд не требуется, а источник файлов не обязан относиться к открытому проекту.

Текущая версия плагина - `0.1.1`. Он использует установленную отдельно командную утилиту Jank Hunter `1.0.0`; её актуальная сборка читает JHLOG `5.0.0` и `5.1.0`. Для журналов Android SDK `1.0.10` нужен CLI с поддержкой новых обязательных возможностей формата. Обновление только плагина IDE не обновляет исполняемый файл CLI.

## Открытие окна

Откройте `Tools → Jank Hunter` или нажмите `Control Alt J`. Плагин использует отдельное немодальное окно: его можно перемещать, изменять размер и держать открытым рядом с редактором.

## Отчёт по одному набору

1. Выберите каталог с журналами.
2. Отметьте один, несколько или все `.jhlog`.
3. При необходимости выберите HPROF или JSON с доказательствами удержания.
4. Нажмите `Сгенерировать отчёт`.

Файлы сортируются по дате и числовому индексу канонического имени сеанса. После успешного запуска сохраняются отпечатки выбранных файлов; при следующем сканировании новые журналы выбираются автоматически. Если истории ещё нет, выбираются все найденные журналы.

В интерфейсе для одного найденного кандидата доступна кнопка `Подставить HPROF`, а при нескольких файлах нужный дамп выбирается через диалог. При пустом поле действует поведение CLI: единственный `retained-*.hprof` рядом с выбранными журналами подключается автоматически; несколько кандидатов требуют явного выбора. Если анализ HPROF не нужен, используйте отдельный каталог только с `.jhlog`.

Путь в HPROF описывает найденный экземпляр класса, но не доказывает его идентичность конкретному объекту, за которым наблюдал SDK. Неизвестный размер и усечение пути показываются отдельно; автоматическое обнаружение дампа само по себе не снижает достоверность.

## Сравнение

Экран `Сравнение` принимает две независимые группы:

- `Было · baseline` - базовые журналы и необязательный HPROF либо JSON-доказательства;
- `Стало · candidate` - проверяемые журналы и необязательный HPROF либо JSON-доказательства.

Один физический файл не может входить в обе группы. Результат - автономный HTML-отчёт сравнения.

Для анализа регрессии выбирайте отдельные прогоны одного сценария в сопоставимых условиях. Несколько сегментов одного запуска не увеличивают число независимых повторов. Копирование файла под другим именем не создаёт новый прогон.

## Чтение отчёта

Страница «Обзор» начинается с проблем приложения, доказательств и рекомендаций. Поиск, фильтры и графы помогают перейти к нужному экрану или классу. Сведения о потерях, неполном покрытии и ограничениях анализа находятся в «Математический анализ → Качество данных», включая отчёт сравнения.

Неизвестное измерение не считается нулём. Сообщение «полнота неизвестна» означает, что объём отсутствующих данных определить нельзя. Покрытие Handler-контекста и измерения первого байта HTTP оценивается отдельно от доставки событий.

## Расширенный режим

Расширенный режим сохраняет выбор простого экрана и предоставляет:

- поиск наборов Gradle-артефактов и ручной выбор `artifacts-dir`, `mapping`, `class-graph`, `instrumentation-diagnostics` и `di-catalog`;
- фильтры `route`, `screen`, `owner` и `class`;
- режим презентации и необязательный движущийся фон;
- оценку пригодности базового и проверяемого наборов;
- путь к утилите, предварительный просмотр команды и диагностическую консоль.

Поиск Gradle-артефактов начинается только при первом открытии расширенного режима. Простой запуск не применяет скрытые фильтры и артефакты из открытого проекта к журналам другого приложения.

Команда `jankhunter problems` поддерживается внутренним конвейером команд, но действие экспорта CSV пока скрыто из интерфейса.

## Каталог отчётов

По умолчанию файлы сохраняются вне проекта:

```text
~/JankHunter/reports/<source>/report-YYYY-MM-DD-HH-mm-ss.html
~/JankHunter/reports/<source>/compare-YYYY-MM-DD-HH-mm-ss.html
```

`<source>` строится из имени каталога с журналами. Путь можно изменить на основном экране или в `Settings → Jank Hunter`. После успешного запуска HTML по умолчанию открывается системным браузером.

## Командная утилита

Плагин ищет исполняемый файл `jankhunter` в типичных местах:

```text
<project>/cli/bin/jankhunter
<project>/../cli/bin/jankhunter
~/.jankhunter/bin/jankhunter
/opt/homebrew/bin/jankhunter
/usr/local/bin/jankhunter
PATH
```

Сборка утилиты из соседнего каталога:

```bash
cd ../cli
make build
./bin/jankhunter version
```

Нестандартный путь задаётся в расширенном режиме или `Settings → Jank Hunter`.

После обновления исходников пересоберите CLI и убедитесь, что в настройках выбран новый исполняемый файл. Команда `version` должна показывать `.jhlog format 5.1.0`; однако поддержка обязательных возможностей может обновляться и без изменения этого номера. Используйте CLI, SDK и Gradle-плагин из согласованной версии исходников. Неподдержанный формат или feature приводит к явной ошибке, а не к частичному отчёту с неверными значениями.

## Конфигурация запуска

Тип `Run Configuration` с именем `Jank Hunter` предназначен для повторяемых и автоматизируемых запусков. Он использует тот же `JankHunterCommandBuilder`, что и основное окно.

Контекстное действие `Inspect Jank Hunter Evidence For Class` открывает расширенный режим и подставляет класс у курсора в фильтр анализа.

## Требования

- IntelliJ IDEA или Android Studio на IntelliJ Platform;
- JBR 21 для сборки и проверки плагина;
- Gradle Wrapper из `plugin-as`;
- доступный исполняемый файл `jankhunter`.

Текущие параметры:

```text
pluginVersion=0.1.1
platformVersion=2026.1.3
pluginSinceBuild=253
```

## Сборка и проверка

```bash
./gradlew test
./gradlew buildPlugin
./gradlew verifyPlugin
```

ZIP создаётся в `build/distributions/`.

Запуск изолированной IDE:

```bash
./gradlew runIde
```

Путь к локальной IDE можно переопределить:

```bash
./gradlew runIde -PlocalIdePath="/Applications/Android Studio.app"
```

## Структура

```text
plugin-as/src/main/kotlin/io/jankhunter/plugin/
  actions/     действия IDE
  execution/   входные модели, поиск файлов, команды и проверка
  problems/    разбор реестра проблем и переход к исходникам
  run/         конфигурация запуска
  services/    процессы, ADB, уведомления и служба проекта
  settings/    сохраняемые настройки
  ui/          основной и расширенный интерфейс окна
```
